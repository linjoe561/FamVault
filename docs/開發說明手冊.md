# FamVault 開發說明手冊

> 版本：0.3（第三階段：購買登錄與庫存）
> 最後更新：2026-10-30

## 1. 系統簡介

FamVault 是家用的庫存管理系統，用來記錄：

- 家裡買了什麼、什麼時候買、在哪裡買
- 每樣東西還剩多少、放在哪裡
- 每一批東西的保存期限，快到期時提醒
- 家人各自登入，系統會記錄是誰用掉的

### 開發進度

| 階段 | 內容 | 狀態 |
|---|---|---|
| 1. 骨架 | 前後端專案、模組化結構、資料庫、登入與家庭成員管理 | ✅ 完成 |

## 2. 開發環境

| 工具 | 版本 | 用途 |
|---|---|---|
| .NET SDK | 10.0 | 後端 |
| Node.js | LTS（目前 26.x） | 前端 |
| SQL Server | 2025 Developer（本機預設執行個體） | 資料庫 |
| dotnet-ef | 10.0 | 建立 Migration（`dotnet tool install --global dotnet-ef`） |

### 第一次啟動

1. 確認 SQL Server 正在執行，而且目前的 Windows 帳號可以登入（Windows 驗證）。
2. 啟動後端（第一次會自動建立 `FamVault` 資料庫與資料表）：

   ```bash
   dotnet run --project backend/src/FamVault.Api
   ```

   - API：http://localhost:5080
   - API 文件（Scalar）：http://localhost:5080/docs
3. 另開一個終端機，安裝前端套件並啟動：

   ```bash
   npm --prefix frontend install
   npm --prefix frontend run dev
   ```

   - 網站：http://localhost:5173
4. 打開網站後，畫面會自動進入「第一次使用」，建立第一位管理者帳號。

### 用手機測試

手機和電腦要連同一個 Wi-Fi。

1. 用以下指令啟動前端（使用自簽憑證的 HTTPS）：

   ```bash
   npm --prefix frontend run dev:https
   ```

2. 終端機會顯示 `Network: https://192.168.x.x:5173`，用手機瀏覽器打開這個網址。
3. 第一次會出現「連線不安全」的警告，選擇「繼續前往」。

> 為什麼要 HTTPS：瀏覽器只允許在 HTTPS 或 `localhost` 下使用鏡頭，之後的掃條碼功能需要它。
> 手機只連到 Vite（5173），Vite 再把 `/api` 轉給本機的後端，所以後端不需要對外開放。

## 4. 架構說明

### 4.1 前後端分離

```
瀏覽器（Vue 3 SPA） ──HTTP/JSON──▶ ASP.NET Core Web API ──EF Core──▶ SQL Server
```

- 前端是純靜態網站，所有資料都經過 `/api/v1/...` 取得。
- 後端不產生畫面，也不使用 Session 或 Cookie，登入狀態由 JWT 承載。
- API 路徑帶版本號（`/api/v1`），以後改版可以並存。
- 錯誤一律回傳 [ProblemDetails](https://www.rfc-editor.org/rfc/rfc9457) 格式。

### 4.2 後端：模組化單體

所有功能部署成一個程式，但內部依功能切成模組。

```
FamVault.Api ──參照──▶ 各模組 ──參照──▶ FamVault.SharedKernel
```

規則：

- 每個模組實作 `IModule`，在 `Program.cs` 的 `modules` 陣列註冊。
- 模組之間**不互相參照**。需要其他模組的資料時，在 `SharedKernel/Contracts` 定義介面，由擁有資料的模組實作。
- 每個模組有自己的 DbContext 與 SQL schema，Migration 也各自獨立。跨模組只存 Id，不建外鍵。

目前的模組：

| 模組 | schema | 內容 |
|---|---|---|
| Identity | `auth` | 家庭成員、登入、角色 |
| Catalog | `catalog` | 分類、位置、單位、品項、條碼 |
| Inventory | `inventory` | 購買登錄、庫存批次、異動紀錄 |

> 原本規劃把「購買」和「庫存」分成兩個模組。實作時合併成 Inventory 一個模組，因為登錄購買時必須在**同一次存檔**中建立庫存批次，分成兩個模組就無法保證不會只成功一半。

跨模組合約（`SharedKernel/Contracts`）：

| 介面 | 實作者 | 使用者 | 用途 |
|---|---|---|---|
| `IUserDirectory` | Identity | Inventory | 查成員顯示名稱（顯示「誰登錄、誰用掉」） |
| `ICatalogLookup` | Catalog | Inventory | 查品項（名稱、單位、預設位置、保存天數、安全庫存）與位置名稱 |
| `ICatalogReferenceChecker` | Inventory | Catalog | Catalog 刪除品項或位置前，詢問是否還有庫存資料在用 |

`ICatalogReferenceChecker` 是「反過來」的合約：Catalog 不認識 Inventory，但會詢問所有註冊的檢查者。以後新增的模組若也會參照品項，只要實作這個介面就能阻止刪除。

#### SharedKernel 提供的功能

| 項目 | 說明 |
|---|---|
| `IModule` | 模組進入點介面 |
| `AuditableEntity` / `IAuditable` | 稽核欄位：`CreatedAt`、`CreatedBy`、`UpdatedAt`、`UpdatedBy` |
| `AuditableEntityInterceptor` | 存檔時自動填入稽核欄位 |
| `AddModuleDbContext<T>()` | 註冊模組 DbContext（獨立 schema 與 Migration 紀錄表） |
| `ICurrentUser` | 取得目前登入者 |
| `AppRoles` | 角色名稱常數（`Admin`、`Member`），各模組的 `[Authorize(Roles = ...)]` 使用 |
| `PagedResult<T>` | 分頁結果 `{ items, total, page, pageSize }` |
| `AppException` 系列 | `NotFoundException`(404)、`ConflictException`(409)、`BusinessRuleException`(400)、`ForbiddenException`(403)、`UnauthorizedException`(401) |
| `AppExceptionHandler` | 把例外轉成 ProblemDetails；`DbUpdateConcurrencyException`（兩人同時修改同一筆）轉成 409 |
| `IAppClock` | `Now` 與 `Today`。`Today` 以家裡的時區計算（設定 `App:TimeZone`，預設 `Asia/Taipei`），不是 UTC 日期 |
| `ValidationActionFilter` | 自動執行 FluentValidation 驗證器，失敗回傳 400 |
| `ApiRoutes.Prefix` | `api/v1` |

#### 模組內部結構

```
Domain/          實體與常數
Application/     Service、DTO、驗證器
Infrastructure/  DbContext、Migration、技術實作
Api/             Controller
XxxModule.cs     註冊模組服務
```

### 4.3 前端：功能模組

```
src/modules/<名稱>/
├── index.js       匯出 { name, routes, nav }
├── api.js         呼叫後端
├── store.js       Pinia 狀態（需要時）
├── views/         頁面
└── components/    模組內元件
```

- `src/app/modules.js` 列出所有啟用的模組，路由與導覽選單會自動組合。
- 子頁面（例如 `/items/5`）在路由 meta 加上 `navGroup: 'items'`，導覽列對應的項目才會亮起。
- 導覽列：首頁、庫存、購買、品項、我的（手機底部最多放 5 個）。「家庭成員」與「分類、位置與單位」的入口放在「我的」頁面（管理者才看得到）。
- 模組之間可以 import 對方的 `api.js` 與 `store.js`（例如 inventory 使用 catalog 的品項搜尋與位置清單），但不要 import 對方的 views 或 components。
- 版面：寬度 900px 以上顯示左側選單，以下顯示底部分頁列。
- 對話框（`AppDialog`）在手機上會變成從底部滑出的面板。

### 4.4 登入與權限

| 項目 | 設計 |
|---|---|
| 帳號 | 用「帳號（UserName）」登入，不需要 Email |
| 密碼規則 | 至少 8 個字元（家用，不強制大小寫與符號） |
| 鎖定 | 連續錯 5 次鎖 5 分鐘 |
| Access Token | JWT，有效 30 分鐘，前端只存在記憶體 |
| Refresh Token | 有效 14 天，前端存在 localStorage；資料庫只存 SHA-256 雜湊 |
| 換發 | 每次換發都撤銷舊的、發新的（輪替）；若收到已撤銷的 Token，視為可能被盜用，撤銷該成員所有 Token |
| 角色 | `Admin`（管理者）、`Member`（成員），權限見下表 |
| 預設 | 所有 API 都要登入，公開端點以 `[AllowAnonymous]` 標示 |

前端流程：

1. App 啟動時，若 localStorage 有 Refresh Token，就換一組新的憑證恢復登入狀態。
2. API 回傳 401 時，自動換發一次並重送原請求；多個請求同時遇到 401 只會換發一次。
3. 換發失敗就清除登入狀態，回到登入頁。

權限：

| 功能 | 成員 | 管理者 |
|---|---|---|
| 查詢品項、分類、位置、單位 | ✅ | ✅ |
| 新增、修改、停用品項（含條碼） | ✅ | ✅ |
| 永久刪除品項（沒有庫存紀錄時） | — | ✅ |
| 購買登錄、查詢庫存、用掉／丟棄、修改批次 | ✅ | ✅ |
| 刪除購買紀錄（還沒被用掉時） | 只能刪自己登錄的 | ✅ |
| 新增、修改、刪除分類／位置／單位 | — | ✅ |
| 管理家庭成員 | — | ✅ |

> 品項開放所有成員新增，是為了之後掃到沒登錄過的條碼時，任何家人都能當場建立。

保護措施：

- 系統至少要保留一位啟用中的管理者（不能把最後一位管理者降級或停用）。
- 管理者停用成員或重設密碼時，會撤銷該成員所有 Refresh Token。
- 已發出的 Access Token 在到期前（最多 30 分鐘）仍然有效。

## 5. API 一覽

所有路徑前綴為 `/api/v1`。完整規格見 http://localhost:5080/docs 。

### 驗證（`/auth`）

| 方法 | 路徑 | 權限 | 說明 |
|---|---|---|---|
| GET | `/auth/setup-status` | 公開 | 是否需要初始設定（還沒有任何成員） |
| POST | `/auth/setup` | 公開 | 建立第一位管理者（已有成員時回傳 409） |
| POST | `/auth/login` | 公開 | 登入 |
| POST | `/auth/refresh` | 公開 | 用 Refresh Token 換發 |
| POST | `/auth/logout` | 公開 | 撤銷 Refresh Token |
| GET | `/auth/me` | 登入 | 目前登入者資料 |
| PUT | `/auth/me/password` | 登入 | 變更自己的密碼 |

登入成功回應：

```json
{
  "accessToken": "eyJ...",
  "accessTokenExpiresAt": "2026-10-30T05:00:00+00:00",
  "refreshToken": "x9...",
  "user": { "id": "…", "userName": "mom", "displayName": "媽媽", "role": "Admin", "isActive": true, "createdAt": "…" }
}
```

### 家庭成員（`/users`，僅管理者）

| 方法 | 路徑 | 說明 |
|---|---|---|
| GET | `/users` | 成員列表 |
| GET | `/users/{id}` | 單一成員 |
| POST | `/users` | 新增成員 `{ userName, displayName, password, role }` |
| PUT | `/users/{id}` | 修改 `{ displayName, role, isActive }` |
| POST | `/users/{id}/reset-password` | 重設密碼 `{ newPassword }` |

### 品項（`/items`）

| 方法 | 路徑 | 權限 | 說明 |
|---|---|---|---|
| GET | `/items` | 登入 | 品項清單（分頁），查詢參數見下方 |
| GET | `/items/{id}` | 登入 | 單一品項 |
| GET | `/items/by-barcode/{code}` | 登入 | 用條碼找品項；找不到回傳 404（掃描時用來引導新增） |
| POST | `/items` | 登入 | 新增品項 |
| PUT | `/items/{id}` | 登入 | 修改品項（含停用 `isArchived`） |
| DELETE | `/items/{id}` | 管理者 | 永久刪除 |

`GET /items` 查詢參數：

| 參數 | 說明 |
|---|---|
| `search` | 名稱部分符合，或條碼完全符合 |
| `categoryId` | 分類；選大分類時也包含底下的小分類 |
| `locationId` | 預設存放位置 |
| `includeArchived` | 是否包含已停用，預設 `false` |
| `page`、`pageSize` | 分頁，預設 1、50（最多 200） |

新增／修改的內容：

```json
{
  "name": "鮮奶 936ml",
  "categoryId": 2,
  "unitId": 2,
  "locationId": 1,
  "safetyStock": 1,
  "shelfLifeDays": 7,
  "note": null,
  "barcodes": ["4710088410019"],
  "isArchived": false
}
```

規則：

- 品項名稱不可重複。
- 條碼會去掉前後空白並轉成大寫，只允許英文字母、數字與 `-`，最長 50 字元；每個品項最多 10 組。
- 條碼在全系統唯一；已屬於其他品項時回傳 409，訊息會說明是哪個品項。

### 分類、位置、單位（`/categories`、`/locations`、`/units`）

三者的端點相同：

| 方法 | 路徑 | 權限 | 說明 |
|---|---|---|---|
| GET | `/{種類}` | 登入 | 清單，含 `itemCount`（使用中的品項數） |
| POST | `/{種類}` | 管理者 | 新增 |
| PUT | `/{種類}/{id}` | 管理者 | 修改 |
| DELETE | `/{種類}/{id}` | 管理者 | 刪除；仍有品項使用時回傳 409 |

內容：

| 種類 | 欄位 |
|---|---|
| 分類 | `{ name, parentId }`：`parentId` 為空代表大分類 |
| 位置 | `{ name, description }` |
| 單位 | `{ name }` |

分類規則：最多兩層；小分類底下不能再放分類；有小分類的分類不能再放到別人底下；同一層名稱不可重複；底下還有小分類時不能刪除。

### 購買登錄（`/purchases`）

| 方法 | 路徑 | 權限 | 說明 |
|---|---|---|---|
| GET | `/purchases?page=&pageSize=` | 登入 | 購買紀錄（新的在前，分頁，預設每頁 20 筆） |
| GET | `/purchases/{id}` | 登入 | 單筆購買 |
| POST | `/purchases` | 登入 | 登錄購買，每一行建立一個庫存批次 |
| DELETE | `/purchases/{id}` | 登錄者或管理者 | 刪除整筆購買（含批次）；任何一批已用掉或調整過時回傳 409 |

登錄內容：

```json
{
  "purchaseDate": "2026-10-30",
  "store": "全聯",
  "note": null,
  "lines": [
    { "itemId": 1, "quantity": 2, "unitPrice": 95, "expiryDate": null, "locationId": null }
  ]
}
```

- `expiryDate` 留空：品項有預設保存天數時，自動算出「購買日期 + 天數」；沒有就是沒有期限。
- `locationId` 留空：使用品項的預設存放位置。
- 購買日期不能是未來；已停用的品項不能登錄。
- 一次最多 50 行；數量 > 0，最多到小數點後 3 位。
- 回應中的 `canDelete` 表示目前登入者能否刪除這筆。

### 庫存（`/stock`）

| 方法 | 路徑 | 說明 |
|---|---|---|
| GET | `/stock` | 庫存總覽，每個品項一列（含沒有庫存的品項） |
| GET | `/stock/items/{itemId}` | 單一品項的批次（先到期的在前）與最近 30 筆異動 |
| POST | `/stock/consume` | 用掉或丟棄 |
| PUT | `/stock/batches/{id}` | 修改批次：更正數量、移動位置、更正到期日 |

`GET /stock` 查詢參數：

| 參數 | 說明 |
|---|---|
| `search` | 品項名稱（部分符合）或條碼（完全符合） |
| `categoryId` | 分類（含小分類） |
| `locationId` | 有庫存放在這個位置的品項 |
| `status` | `all`（預設）、`inStock` 有庫存、`outOfStock` 沒有了、`expiring` 已過期或 7 天內到期（依到期日排序）、`low` 低於安全庫存 |
| `page`、`pageSize` | 分頁，預設 1、50 |

每列包含 `quantity`（總數量，含已過期）、`expiredQuantity`、`nearestExpiry`、`expiryStatus`、`isLow`、`locationNames`。已停用的品項只有在還有庫存時才列出。

用掉／丟棄：

```json
{ "itemId": 1, "quantity": 1, "kind": "consume", "batchId": null, "note": null }
```

- `kind`：`consume` 用掉、`discard` 丟棄。
- `batchId` 留空時採「先到期先用」：從到期日最早的批次開始扣（沒有到期日的排最後，再依購買日），一批不夠就扣下一批，每一批各留一筆紀錄。
- 數量超過庫存時回傳 400，訊息會說明還剩多少。

修改批次：

```json
{ "quantity": 3, "locationId": 2, "expiryDate": "2026-11-02", "note": "盤點" }
```

`quantity` 是「實際剩下的數量」，和原本不同時會留下一筆「調整」紀錄（數量差）。

保存期限狀態 `expiryStatus`：

| 值 | 意義 |
|---|---|
| `expired` | 已過期 |
| `soon` | 7 天內到期（含今天） |
| `upcoming` | 30 天內到期 |
| `ok` | 還早 |
| `none` | 沒有到期日 |

```json
{
  "title": "輸入資料有誤",
  "status": 400,
  "errors": { "password": ["密碼至少需要 8 個字元"] }

```

```json
{ "title": "無法完成操作", "status": 400, "detail": "至少要保留一位啟用中的管理者" }
```

`errors` 的欄位名稱是 camelCase，前端直接對應到表單欄位。清單欄位的錯誤會帶索引（例如 `barcodes[1]`），前端會歸到 `barcodes` 欄位顯示。

## 6. 資料庫

- 資料庫：`FamVault`
- 每個模組一個 schema，各有自己的 `__EFMigrationsHistory`。

### schema `auth`（Identity 模組）

| 資料表 | 說明 |
|---|---|
| `Users` | 成員。除了 Identity 標準欄位，另有 `DisplayName`、`IsActive`、`CreatedAt` |
| `Roles` | 角色（Admin、Member，由 Migration 建立） |
| `UserRoles` | 成員與角色的對應 |
| `RefreshTokens` | `UserId`、`TokenHash`、`CreatedAt`、`ExpiresAt`、`RevokedAt` |
| `UserClaims`、`UserLogins`、`UserTokens`、`RoleClaims` | Identity 標準資料表（重設密碼憑證等） |

### schema `catalog`（Catalog 模組）

| 資料表 | 說明 |
|---|---|
| `Categories` | 分類：`Name`、`ParentId`（最多兩層）、`SortOrder` |
| `Locations` | 存放位置：`Name`（唯一）、`Description`、`SortOrder` |
| `Units` | 單位：`Name`（唯一）、`SortOrder` |
| `Items` | 品項：`Name`（唯一）、`CategoryId`、`UnitId`、`LocationId`（預設存放位置）、`SafetyStock`（安全庫存量）、`ShelfLifeDays`（預設保存天數）、`Note`、`IsArchived` |
| `ItemBarcodes` | 條碼：`ItemId`、`Code`（全系統唯一） |

以上資料表（除了 `ItemBarcodes`）都有稽核欄位 `CreatedAt`、`CreatedBy`、`UpdatedAt`、`UpdatedBy`。

預設資料（由 Migration 建立，可以自行修改或刪除）：

- 分類：食品、飲料、調味料、日用品、清潔用品、個人保養、藥品
- 位置：冰箱冷藏、冰箱冷凍、廚房櫃、儲藏室、浴室
- 單位：個、瓶、罐、包、盒、袋、條、卷、片、公斤、公克、公升、毫升

> 品項的「實際數量」與「保存期限」不在這裡，由 Inventory 模組的「批次」記錄。
> 有庫存紀錄的品項只能停用、不能永久刪除；還有庫存放著的位置不能刪除。

### schema `inventory`（Inventory 模組）

| 資料表 | 說明 |
|---|---|
| `Purchases` | 一次採買：`PurchaseDate`、`Store`、`Note`＋稽核欄位（`CreatedBy` 就是登錄的人） |
| `PurchaseLines` | 採買明細：`PurchaseId`、`ItemId`、`Quantity`、`UnitPrice` |
| `StockBatches` | 庫存批次：`ItemId`、`LocationId`、`PurchaseLineId`、`PurchasedOn`、`ExpiryDate`、`InitialQuantity`、`RemainingQuantity`、`RowVersion`＋稽核欄位 |
| `StockTransactions` | 異動紀錄：`StockBatchId`、`ItemId`、`Type`（Purchase／Consume／Discard／Adjust）、`QuantityChange`（入庫正、用掉負）、`OccurredAt`、`UserId`、`Note` |

設計重點：

- 「家裡還有多少」＝ 該品項所有批次 `RemainingQuantity` 的加總。
- 所有數量變化都經過 `StockBatch.Record()`，同時更新 `RemainingQuantity` 並新增一筆異動紀錄，兩者不會不一致。異動紀錄只新增、不修改。
- `RowVersion` 是樂觀鎖：兩位家人同時扣同一批時，後送出的人會收到 409，請他重新整理。
- `ItemId`、`LocationId`、`UserId` 都是其他模組的 Id，不建外鍵。

> 用 `sqlcmd` 修改資料時請加上 `-I`，例如：
> `sqlcmd -S . -E -C -I -d FamVault -Q "SELECT * FROM auth.Users"`

### 建立 Migration

```bash
cd backend
dotnet ef migrations add <名稱> \
  --project src/Modules/<模組>/FamVault.Modules.<模組> \
  --startup-project src/FamVault.Api \
  --context <模組>ModuleDbContext \
  --output-dir Infrastructure/Migrations
```

`<模組>` 目前有 `Identity`、`Catalog`、`Inventory`。

> ⚠️ 新增 Migration 後，要先 `dotnet build` 整個方案，再用 `--no-build` 啟動 API；否則 API 用的是舊的組件，Migration 不會被套用，會出現「無效的物件名稱」錯誤。

開發環境下（`Database:AutoMigrate = true`），API 啟動時會自動套用。

## 7. 設定

### 後端（`backend/src/FamVault.Api/appsettings*.json`）

| 設定 | 說明 | 開發環境值 |
|---|---|---|
| `ConnectionStrings:Default` | 資料庫連線字串 | 本機 `.`、Windows 驗證 |
| `Jwt:SigningKey` | JWT 簽章金鑰，至少 32 字元 | 開發用金鑰（**正式環境必須更換**） |
| `Jwt:AccessTokenMinutes` | Access Token 有效分鐘 | 30 |
| `Jwt:RefreshTokenDays` | Refresh Token 有效天數 | 14 |
| `Cors:AllowedOrigins` | 允許呼叫 API 的前端網址 | `http(s)://localhost:5173` |
| `Database:AutoMigrate` | 啟動時自動套用 Migration | true |
| `App:TimeZone` | 計算「今天」用的時區（判斷到期、購買日期） | 未設定時為 `Asia/Taipei` |

正式環境請用環境變數覆寫，不要把金鑰寫進檔案：

```bash
Jwt__SigningKey=<至少 32 字元的隨機字串>
ConnectionStrings__Default=<連線字串>
```

### 前端（`frontend/.env`）

| 設定 | 說明 |
|---|---|
| `VITE_API_BASE_URL` | API 位址，預設 `/api/v1`（同網域）。前後端不同網域時填完整網址 |
| `VITE_API_PROXY_TARGET` | 開發伺服器轉送 `/api` 的目標，預設 `http://localhost:5080` |
| `VITE_DEV_HTTPS` | 只在 `.env.https` 設為 `true`，啟用自簽 HTTPS |

## 8. 測試

```bash
dotnet test backend
npm --prefix frontend run build
```

目前的單元測試：

- `TokenServiceTests`：JWT 內容與簽章、Refresh Token 隨機性與雜湊
- `AuditableEntityInterceptorTests`：稽核欄位自動填入
- `ItemServiceTests`：條碼正規化與去重、條碼與名稱重複、修改條碼、清單篩選（停用、大分類含小分類）
- `LookupServiceTests`：分類兩層限制、使用中不可刪除、單位名稱重複

- `InventoryServiceTests`：購買帶入預設到期日與位置、未來日期與停用品項、先到期先用跨批次扣除、庫存不足、購買刪除限制、總覽的狀態篩選（沒有了、快過期、該補貨）、批次調整紀錄、到期狀態門檻

Catalog 的服務測試使用 EF Core InMemory 資料庫（含預設種子資料），見 `tests/FamVault.Tests/Catalog/CatalogTestDb.cs`。
Inventory 的測試用假的 `ICatalogLookup`、`IUserDirectory`、`ICurrentUser`、`IAppClock`（今天固定為 2026-10-30）取代其他模組，見 `tests/FamVault.Tests/Inventory/InventoryTestContext.cs`。

API 可用 `backend/src/FamVault.Api/FamVault.Api.http`（VS Code REST Client 或 Visual Studio）手動測試。

### 不影響自己資料的整合測試

本機資料庫已經有家人的帳號時，可以讓測試用的後端連到另一個資料庫：

```bash
ConnectionStrings__Default="Server=.;Database=FamVault_Test;Trusted_Connection=True;TrustServerCertificate=True" \
ASPNETCORE_ENVIRONMENT=Development \
dotnet run --project backend/src/FamVault.Api --no-launch-profile --urls http://localhost:5081
```

前端要轉到這個後端時，建立 `frontend/.env.development.local`（不會被提交）：

```
VITE_API_PROXY_TARGET=http://localhost:5081
```

測完刪除該檔案，並刪除 `FamVault_Test` 資料庫。

## 9. UI 與設計規範

- 風格定位：溫暖、有生活感的家用質感（米白紙感底色、深咖啡文字、鼠尾草綠、陶土橘、芥末黃）。**避免 SaaS 風格的藍紫漸層與冰冷配色。**
- 所有顏色、字體、圓角、間距都定義在 `frontend/src/design/tokens.css`，元件內不寫死數值。
- 目前的 tokens 是暫定值。拿到 Claude Design 的設計後：
  1. 替換 `tokens.css` 的數值
  2. 視需要調整 `shared/components/` 內元件的樣式
  3. 替換 `AppIcon.vue` 的圖示路徑
- 元件行為（對話框、下拉選單等）使用 Reka UI，它不帶任何外觀，不會和設計衝突。
- 手機優先：觸控目標至少 44px，輸入框字級至少 16px（避免 iOS 自動放大）。
- 到期狀態不只用顏色區分，也要搭配文字或圖示。

## 10. 新增功能的步驟

以下一階段的「提醒（Notifications）」為例。詳細指令見 `.claude/skills/famvault-dev/SKILL.md`，跨模組的完整範例可參考 Inventory 模組。

1. 建立後端模組專案 `FamVault.Modules.Notifications`，參照 SharedKernel。
2. 寫 Domain 實體（繼承 `AuditableEntity`）、`NotificationsModuleDbContext`（schema `notify` 之類，避開保留字）。
3. 寫 Service、DTO、驗證器、Controller。
4. 寫 `NotificationsModule : IModule`，在 `Program.cs` 註冊。
5. 建立 Migration，接著 `dotnet build`。
6. 需要庫存資料時，在 `SharedKernel/Contracts` 定義介面（例如 `IStockAlertSource`），由 Inventory 實作，不要直接讀 `inventory` schema。
7. 建立前端模組 `src/modules/notifications/`，在 `src/app/modules.js` 註冊。
8. 寫單元測試（其他模組用假實作取代），更新本手冊與使用者手冊。

## 11. 部署（之後）

目前只在本機使用。之後要放到家裡的電腦或 NAS 時：

1. `npm --prefix frontend run build` 產生 `frontend/dist/` 靜態檔。
2. `dotnet publish backend/src/FamVault.Api -c Release` 產生後端程式。
3. 用 Nginx 之類的伺服器提供前端靜態檔，並把 `/api` 轉給後端；或用 Docker Compose 分成前端、後端、資料庫三個容器。
4. 設定正式的 `Jwt__SigningKey`、連線字串、`Cors__AllowedOrigins`。
5. 使用正式的 HTTPS 憑證（手機掃條碼需要）。

## 12. 常見問題

| 狀況 | 原因與處理 |
|---|---|
| 前端顯示「無法連線到伺服器」 | 後端沒有啟動，或不是跑在 5080 port |
| API 啟動時出現 `Jwt:SigningKey 至少需要 32 個字元` | 目前環境沒有設定金鑰。開發時確認 `ASPNETCORE_ENVIRONMENT=Development` |
| sqlcmd 執行 DELETE 出現 `QUOTED_IDENTIFIER` 錯誤 | 加上 `-I` 參數 |
| 手機上無法使用鏡頭 | 必須用 `npm run dev:https` 啟動，並用 `https://` 網址開啟 |
| 忘記管理者密碼 | 若還有其他管理者，請他重設。若沒有，可以刪除 `auth.Users` 中所有成員，系統會回到「第一次使用」畫面（**會失去所有成員帳號**） |
| 安裝 Node.js 後找不到 `npm` 指令 | 重新開啟終端機，讓新的 PATH 生效 |
